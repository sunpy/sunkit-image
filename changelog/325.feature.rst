Added an opt-in analytic fast path to `~sunkit_image.utils.find_pixel_radii` via a new keyword-only ``fast`` argument (default `False`). For non-rotated helioprojective-Cartesian maps, ``fast=True`` computes the radii directly from the WCS header values, bypassing the ``smap.wcs.pixel_to_world`` SkyCoord round-trip; on a 4096x4096 map the call drops from about 1 s to 150 ms. This path is approximate -- it assumes the reference coordinate is near Sun center and uses a tangent-plane treatment of the sky offsets, so its accuracy degrades away from disk center and it is not used unless explicitly requested. The default (``fast=False``), rotated maps, and non-helioprojective frames all use the exact SkyCoord-based calculation unchanged; near disk center ``fast=True`` matches it to better than 2e-4 R_sun on a 4096x4096 map at 2"/pixel (and to floating-point precision on AIA-scale maps). `~sunkit_image.utils.blackout_pixels_above_radius` also gained a keyword-only ``map_r`` argument so callers that already hold the pixel-radius array can reuse it instead of paying for a second `~sunkit_image.utils.find_pixel_radii` call; `~sunkit_image.radial.rhef` now threads its own ``map_r`` through, eliminating the duplicate WCS pass it used to make for the vignette step.
