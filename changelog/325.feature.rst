Sped up `~sunkit_image.utils.find_pixel_radii` and the functions that use it. For non-rotated helioprojective-Cartesian maps the radii are now computed directly from the WCS header values, bypassing the ``smap.wcs.pixel_to_world`` SkyCoord round-trip; on a 4096x4096 map the call drops from about 1 s to 150 ms. Rotated maps and non-helioprojective frames fall through to the existing SkyCoord-based path unchanged, and the new output matches the old to better than 2e-4 R_sun on a 4096x4096 map at 2"/pixel (and to floating-point precision on AIA-scale maps). `~sunkit_image.utils.blackout_pixels_above_radius` also gained a keyword-only ``map_r`` argument so callers that already hold the pixel-radius array can reuse it instead of paying for a second `~sunkit_image.utils.find_pixel_radii` call; `~sunkit_image.radial.rhef` now threads its own ``map_r`` through, eliminating the duplicate WCS pass it used to make for the vignette step.
